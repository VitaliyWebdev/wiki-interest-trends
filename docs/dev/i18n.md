# i18n.py — English + Ukrainian

**File:** `skills/wiki-interest-trends/scripts/wikitrends/i18n.py`
**Tests:** `skills/wiki-interest-trends/tests/test_i18n.py`

```python
SUPPORTED_LANGS = ("en", "uk")
DEFAULT_LANG = "en"
pick(table: Mapping[str, T], lang: str) -> T
```

The skill has three separate user-facing string tables:
`report.LABELS` (PDF headings and table values), `chart.CHART_LABELS`
(chart title, y-axis, "peak" markers), and `trust.REASON_TEMPLATES`
(trust reasons). Each is keyed by language. `pick()` is the single rule
all three use to look up a language: return the requested one, or fall
back to `DEFAULT_LANG` for anything unsupported. An unsupported language
gives a less-localized output, never a `KeyError`. Before this module
each table had its own copy of that `.get(lang, table["en"])` line.

## The parity test is the actual safety net

Because `pick()` falls back silently, a missing Ukrainian string never
crashes anything. You just get a quietly half-English PDF, which is the
exact class of bug this project has shipped twice (English trust reasons,
then an English chart, inside a Ukrainian report; see `report-pdf.md`).
`test_every_user_facing_string_table_covers_every_supported_language`
walks every table and asserts that each supported language has exactly
the same keys (nested dicts and list lengths included) as `DEFAULT_LANG`.
Adding a string in one language without the other fails CI.

## Adding a language

1. Add the code to `SUPPORTED_LANGS`.
2. Add that language's entry to `report.LABELS`, `chart.CHART_LABELS`, and
   every `trust.REASON_TEMPLATES` code. The parity test lists anything
   missed.
3. Add its trigger phrases to `SKILL.md`'s `description`. Without them the
   skill won't auto-trigger for people writing in that language
   (anthropics/claude-code#68086), however good the rest of the
   translation is.
4. Add eval scenarios phrased in that language to `evals/evals.json`.

## What is deliberately *not* localized

- `SKILL.md`, `references/`, error `hint`s, and `trust.reasons` in
  `analysis.json`. These are read by the agent, not the user, and the
  agent is told to answer in the user's language.
- `Mann-Kendall`, `YoY`, and language codes in the PDF table. These are
  standard terms, not prose.
- The CLI flags. Note that `analyze.py --lang` (with `--titles`) is a
  Wikipedia *edition*, while `report.py --lang` is the *output*
  language. `SKILL.md`'s Language section spells out the difference for
  the agent.
